# 运维、备份恢复与升级

## 日常运行

- /api/v1/health 验证数据库连通、任务模式和外部能力配置标记。模型或发布“已配置”不代表真实调用验收已通过。
- 关注失败、待授权、待核实和长时间排队任务。已知429限流采用有限次数延迟重试；不要对未知提交状态强制重复执行。
- 监控主机磁盘、S3容量、模型额度预占、Celery队列积压、容器内存、邮件失败及浏览器扫码过期。日志仅使用任务编号和错误代码，不打印模型Key、回调密文或家长联系方式。
- 云监控应在部署时接入服务可用性与队列告警；本包没有连接真实告警接收人或发送通知。
- 免费期与机构额度在平台管理中调整。套餐分配是权益配置，未触发在线收费。
- 使用 scripts/doctor.py 执行只读检查；报告不调用付费模型或发帖。

发布任务重试接口只接受尚未提交平台的失败/待授权任务。结果未知先调用 reconcile。媒体恢复只接受已存在供应商任务ID、已取得结果URL或已转存原始素材，不会新建未知付费任务。接口详见 OpenAPI。

## 备份

本地开发可直接运行：

    .\.venv\Scripts\python.exe scripts/backup.py --directory .local/backups

SQLite使用在线一致性备份，同时复制本地对象，记录文件SHA-256；不包含加密主密钥。

生产环境安装与服务器主版本匹配的 pg_dump，运维通过受控环境变量 OPS_BACKUP_DATABASE_URL 提供备份角色连接信息。运行角色的RLS会限制备份，因此应使用独立的只读备份权限角色/运维凭证，不能为了备份提升Web运行角色。

    python scripts/backup.py --directory /受控加密备份目录

工具生成自定义格式PG备份和S3对象清单。**S3清单不是对象备份**：需为桶启用版本控制、跨账号/跨区域复制或云备份，并保存与数据库备份时间对应的版本。对象Key不包含访问凭证，清单与业务备份仍须限制访问。

浏览器加密状态卷位于独立发布主机，需单独备份相应卷并保存网关密钥。OPS_SECRET_KEY及发布网关主密钥保存在独立的密钥管理/保险库，不能与业务压缩包一起分享。更换主密钥前需要重新加密既有凭证，不能简单替换环境变量。

## 恢复演练

SQLite恢复要求全新目标路径：

    python scripts/restore.py .local/backups/备份时间目录 --sqlite-destination .local/restore-check.sqlite

工具校验清单及数据库完整性，不覆盖已有文件。对象目录按备份另行恢复到独立目录，确认完整后再切换运行配置。

PG演练使用独立空数据库，名字必须以 _restore 结尾。提供 OPS_RESTORE_DATABASE_URL 后运行：

    python scripts/restore.py /备份时间目录

工具不使用 DROP 或 --clean，不会清理已有目标。恢复演练和切换期间先关闭真实发布及自动计划，核对备份时间之后的外部作品、付费任务与银行流水再重新启用。恢复后需确认账号角色、RLS策略、迁移版本、关键业务行数、金额流水总额、课时余额、附件哈希、私有对象访问与跨机构拒绝，再决定切换。脚本完成不等于生产恢复验收完成。

## 升级和回滚

1. 固定当前应用与浏览器镜像摘要，导出部署配置和迁移版本。先执行数据库/对象/浏览器卷备份。
2. 在独立预发布环境恢复备份，部署新版本，先用迁移角色执行 Alembic，运行回归及跨机构访问检查。
3. 通过后再更新生产应用与Worker；停止旧Beat后启动新Beat，避免重复调度。调度的唯一请求键和任务CAS保护仍然有效。
4. 验证健康、四条业务流程、已存在视频任务继续轮询、未知发布任务保持不重发、费用预占没有重复。
5. 若数据库迁移向后兼容，恢复上一个应用镜像摘要并重新验证。破坏性数据库变更不能仅回滚代码，应使用已演练的恢复方案。
6. 首次迁移禁止破坏性downgrade。后续变更必须新增迁移，不改写已经部署的0001历史。

本机未具备Docker/原生PG，故容器升级、镜像扫描、云端对象恢复与生产回滚尚未实际演练。交付报告中保持待验证，部署时记录操作者、时间、镜像摘要和证据。

## 0.3 数据与恢复

新增14张机构表，用于不可覆盖业务事件、课次名册、课返考核、扫描任务、表单版本、审批实例/待办、报表、异常、通知发件箱、票据关联和增值申请。备份必须包含全部数据库表、私有对象和独立保管的原加密主密钥。

迁移 `0003_operations` 只新增业务结构和历史订单快照，不改写既有财务/课时流水。旧在读日期缺失时保留待校准，旧课返完成率不推断。恢复后的经营推送先保持未配置/停用，核实结果未知的通知后再恢复调度，防止重复推送。

SQLite 恢复演练和原生 PostgreSQL 恢复分别记录，当前本地演练结果见 `backup-restore-03.json`。实际生产回滚必须使用与镜像匹配的已验证备份。
