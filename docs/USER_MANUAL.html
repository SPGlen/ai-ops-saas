知营使用说明书

教育机构运营工作台与自媒体账号接入指南

适用版本 0.4.0 rc1　｜　检查日期 2026年10月23日　｜　适用人员 机构负责人 员工 部署维护人员

知营用于协同管理招生、学员、教务、课返完成考核、财务、经营报表和自媒体矩阵。一人可以兼任多个岗位，也可以由多人分工；负责人统一分配功能授权。

当前页面属于独立企业演示环境。账号列表可以展示和建档，但真实扫码、模型调用、发布及回复均被拦截。接入真实平台必须使用另外的测试环境，并先连接发布执行节点。

员工通过负责人发出的邀请加入指定机构，不需要另建自己的机构。一个账号可以加入多个机构，操作前先核对页面右上方的当前机构。

负责人如何分配

  1. 进入成员与授权，邀请员工时填写邮箱并勾选岗位。邀请24小时有效，可撤销，只能接受一次；正式环境需要可用邮件服务。
  2. 已有员工点击调整授权，可以同时选择多个岗位；保存后后续请求和未执行任务会重新校验。
  3. 员工离职时停用其成员资格。至少保留一名有效负责人，不能把最后一名负责人撤销或停用。
兼任按具体操作合并。例如授课加营收查看可以看营收汇总，学员和家庭反馈仍限任教范围。平台管理员管理机构权益，访问业务也需要该机构成员身份。

企业演示中的角色选择和切换仅用于展示。演示环境不发送真实邀请邮件；正式使用时不要共享演示密码。

招生录入和报名

入口为招生线索。先建立线索，再记录联系、预约、到场和报名；纸表或Excel中的收款标记不能代替财务登记。

招生表的使用

  1. 下载系统Excel模板或打印PDF模板。为每个孩子保留稳定线索编号，同一家长的不同孩子分行填写。
  2. 填写学员、年级、家长及关系、家长手机号、来源、意向班级、负责人、预约、阶段和备注。正在跟进的记录无需虚构流失原因。
  3. 上传Excel，或在启用OCR的环境上传清晰图片和多页PDF。单文件最多25MB、PDF最多20页、最多500行。
  4. 识别后对照原件逐行检查，处理低置信度、重复候选、负责人和班级匹配，再选择确认导入。缺编号时人工选择候选，不能只凭手机号合并。
  5. 导入后更新联系阶段、跟进时间和预约。记录试听到场；未成交需填写实际原因。状态以系统中的业务记录联动。
当前企业演示可实际解析Excel；图片和PDF真实OCR关闭。扫描到已收款、已报名或已退费时只进入待核对信息，不会自动产生账款。

从线索到正式报名

  1. 为学员建立档案，在财务台账或有权限的课程订单入口新增报名订单。直接填写项目名称、金额、优惠、购买课时、招生负责人，并关联线索及可选班级。
  2. 财务核对实际到账，登记收款。定金可以单列，未缴清不计正式报名转化。
  3. 缴清应收后，在教务管理的报名与课时中确认报名和课时账户，必要时分班。正式报名状态由这些业务记录产生。
状态实际含义
已预约已确认试听安排，尚未说明到场或付款
已到场已经试听，不自动等于正式报名
正式报名缴清应收并完成报名课时确认
未成交结束本轮跟进，保留实际原因

列表、关联下拉、导出和报表均按当前岗位过滤。多人页面会持续刷新；如出现版本冲突，先刷新读取最新记录，再修改。

学员档案和教务

学员档案

  1. 进入学员档案，按班级查看，或搜索学员、家长和手机号；可以筛选老师和在读状态。
  2. 点击学员，查看家长姓名、关系、手机号、档案备注、报名、剩余课时和出勤。按实际情况维护多个家长；不同孩子分别建档。
  3. 分班、调班、退班使用对应业务入口并记录生效时间和原因，不用普通编辑覆盖报名历史。

排课 签到 请假和补课

  • 排班人员维护课次时间、时长和状态。教师只操作任教班级；教务授权不自动包含排课修改。
  • 签到每次扣减1课时；同一报名同一课次重复签到不重复扣减。已结束的报名不能继续签到。
  • 批准请假后原课不扣课时，补课安排到另一实际课次，再按实际到课签到。课时调整由有权限人员填写原因并留痕。

课返完成考核和家庭反馈

老师在排课或签到相关页面确认本班本课次的课返是否完成。默认课程结束后24小时截止，取消课次不考核；教务纠正记录必须写原因。不再编辑或AI生成课返正文。

学员家长反馈另行记录教学、课程安排、服务等真实意见及可选1至5分评分。处理后填写结果。家庭反馈与教师课返KPI是两类记录，未评分不推断为满意。

05 / 14

财务台账和票据

  1. 在财务台账选择期间、班级或来源，查看实收、退款、净收、已确认费用及收支差额。点击图表定位相关明细。
  2. 点击订单或查看票据与详情，检查关联收款、费用、票据原件、识别草稿、核对和操作记录。可以关联多张图片或PDF。
  3. 按真实发生登记收款、费用或退款。OCR和AI提取只提供草稿，财务核对后才确认入账；当前演示不运行真实OCR。

登记退款

  • 先核对购买、已上、未上课时及调整明细；填写实际退款金额和必填原因，系统保存退款当时的课时快照。
  • 部分退款但继续就读时保留报名关系，不计流失。退读退费时明确结束哪些报名；同一学员仍有其他有效报名时不计机构学员流失。
  • 误登记使用有依据的冲正或调整，保留原流水；不要重复新增一笔退款来抵消错误。
系统是财务台账，不执行银行转账、银行退款或发票开具。营收图表为已登记现金口径，不等于按课时确认收入，也不能直接视为利润。

财务可看必要的学员关联资料，但不能因此读取任课内容和家庭反馈。仅有整体营收查看授权的人员不能进入票据和交易明细。

周报月报和异常提醒

经营周报和月报汇总招生、在读变化、出勤、课返、现金收支及家庭反馈。当前经营文字摘要由确定性规则生成，真实AI润色需另接模型。

指标系统口径
线索转化率本周新增线索中截至统计时正式报名数，除以本周新增线索数；跨周成交回补原批次。
试听转化率本周首次到场的线索中截至统计时正式报名数，除以本周首次到场线索数。
新增在读本期首次缴清并确认报名的去重学员；续费和重新入读另列。
月度流失率本月退读人数，除以月初在读和本月新增在读的去重人数。
月度出勤率已结束课次的实到人次，除以应到人次；批准请假仍是未出勤，取消课次不计。

查看和保存报告

  1. 进入经营周报 / 月报，选择周期。查看当前授权范围内的指标及原因明细；负责人可以查看机构完整报告。
  2. 已保存报告是快照，不覆盖旧版。补录和冲正后需要更正版时生成新版本，比较版本时核对生成时间。
  3. 缺分母显示暂无数据，缺历史期初或日期时标为待校准；先补齐依据，不能把缺失改成零。

异常和管理群推送

负责人在经营规则与提醒设置阈值、适用班级、报告时间和管理群机器人。默认流失率达到或超过30%触发异常，记录触发值、周期、关联明细和处理意见；恢复后保留历史。

默认中国时区每周一09:00生成上周周报，每月1日09:00生成上月月报。正式环境需Worker和调度器运行；企业演示关闭自动调度和真实群推送。

通知只发送经营摘要和登录查看链接，不含儿童资料、手机号或家庭反馈原文。结果未知时先到群里核实，再决定是否重试。管理群通知与暂停的微信AI客服独立。

表单流程和社群运营

表单与流程

  1. 负责人进入表单与流程，新建定义或加载模板。表单可添加字段、排序、分组、必填、选项、条件显示和岗位读写限制。
  2. 流程画布连接开始、填写、审批、条件、并行、通知、业务动作和结束节点。选择实际审批岗位或成员；发布前检查分支、审批人和权限。
  3. 先预览和试运行，确认后发布。独立表单可提交申请；需要约束费用、退款等业务时，另外启用对应业务流程。
场景是否拦截原业务
财务直接登记默认保留，可以按权限直接登记
已发布但未启用的业务流程仍不拦截原业务
已发布且已启用的对应业务流程原业务接口同时检查审批，不可绕过
独立表单和独立流程按显式提交运行，不必启用业务拦截

提交实例固定表单及流程版本，新版本只影响新提交。退回后修改关键数据需重新审批；审批人停用时转负责人待分配，不自动通过。财务实际发生确认仍由财务完成。

社群运营

  1. 建立活动任务，填写目标家庭分组、文案、计划时间和实际发送渠道。
  2. 当前主要使用员工人工发送路径。员工在官方渠道实际处理后，登记真实的触达、跟进和转化结果。
  3. 没有已授权发送渠道时只保存文案和任务，不会自动给家长群发送。
网页咨询、微信AI客服、评论和私信自动回复当前暂停。数字人直播入口已隐藏，真实数字人直播未接入。演示中已有的活动和审批案例仅为虚构业务示例。

自媒体账号接入总览

入口为自媒体矩阵。账号连接不是在网页中填写平台密码，也不是粘贴任意MCP网址。系统通过平台维护的发布执行节点，为每个机构和每个平台账号管理独立登录状态。

顺序组件谁负责
1网页矩阵账号中心负责人填写品牌和账号资料并发起扫码
2FastAPI业务后端检查机构、岗位、预算、计划和任务版本
3受控发布网关部署人员设置地址及认证，转发允许的MCP工具
4机构执行环境内的独立账号上下文对应平台扫码、身份回读、发布和结果核实

  • 向账号登录接口发起不对外发送的检查，返回409 DEMO_EXTERNAL_DISABLED。这是演示隔离措施，不是二维码扫码失败。
  • 添加账号可保存平台、备注、品牌、定位和预算；这一步只建档，不代表已经绑定真实账号。

开始连接前准备

  • 负责人账号和目标机构已确认；已建立品牌、确认知识库并标明素材授权。
  • 发布网关可达、浏览器环境可运行，小红书固定版本MCP二进制可用。
  • 持有各平台账号的有权人员可逐个扫码；先关闭真实发送，完成身份和只读能力检查。

负责人连接账号的操作

  1. 在品牌与分组先建立品牌，填写受众和风格，选择已审核知识库及授权素材。
  2. 回到矩阵账号，点击添加账号。填写账号备注，选择平台与品牌，设置定位、引导语、默认形式和账号月预算。
  3. 保存后，在该账号行点击扫码登录。执行环境生成二维码或登录页面截图，由对应平台手机应用扫码；每个账号分别完成。
  4. 点击扫码后检查身份，或勾选账号后批量检查身份。核对平台实际账号ID；不能只看昵称、备注或已登录文字。
  5. 点击核验能力，查看逐项状态和具体原因。小红书当前会额外尝试搜索能力；发布和指标仍分别需要真实回执。
  6. 同品牌账号可加入一个或多个分组。同平台多个账号分别扫码；重叠分组在新运行创建时去重，不会重复投递。
配置和扫码由负责人控制。内容运营可以操作本机构全部账号的内容和任务，不能自行绑定账号、提高预算或扩大自动发布策略。

如何理解页面状态

  • 未连接或待授权：先检查执行节点和登录状态；出现验证码或账号异常时到官方端处理。
  • 已登录或已连接：表示登录检测通过，不自动说明真实账号身份和发布能力已核实。
  • 身份已核实：连接器回读到可靠账号ID。同机构重复绑定同一平台账号会被拦截；发现身份改变会暂停并要求重新核验。
  • 能力待验证：需要对应能力的真实测试。可用才说明已验证这一项；不支持的项目使用官方后台人工操作。
核验能力按钮不会发送一篇测试作品，也不会替代评论、私信的官方授权。三平台真实账号尚未在当前项目完成验收，不承诺扫码后即可全自动运营。

真实发布后必须保存可核实的作品编号和链接。视频号当前的稳定身份适配仍是无人值守接入的明确阻塞项；不能人为填写身份标志绕过。

内容制作和预算

品牌是知识、受众、风格和素材的边界。进入内容工作室管理选题、素材和成品；进入自媒体矩阵管理多账号的版本化运营计划。内容工作室里的旧自动计划只保留历史提示。

建立运营计划

  1. 选择品牌，明确选择账号或分组。母题矩阵模式共享选题，按账号生成不同内容；独立运营模式按账号定位分别选题。
  2. 选择常青选题、平台允许的RSS/Atom来源或已验证的小红书搜索。外部Feed域名由平台维护白名单。
  3. 设置星期、时刻、制作方式、视频时长、审核方式和费用来源。默认中国时区周二、周五18:00、视频45至90秒、逐条审核；每个计划最多12个时刻。
  4. 保存计划。内容运营保存的版本需负责人授权试运行预算；预算或策略调整后形成新版本，并重新核验。
预算层级用途
平台额度或机构自带Key确定实际用哪套模型凭证；不足不自动换Key
机构月预算限制整个机构矩阵的模型支出
账号月预算限制该账号任务的支出
计划日预算和单次预算限制计划当天及单次运行费用

未配置额度或预算按零处理。机构、账号、计划多个约束共同生效，调用前预占，完成后按实际用量结算；共享选题成本单列一次。软件使用期与模型额度分开展示。

试运行的费用和结果

试运行不自动发布，但在正常测试环境会调用模型并可能收费，不能把它当免费预览。企业演示环境会阻止实际生成。执行预览只展示目标和预算范围，不产生模型成品。

视频可用程序合成、AIGC或混合制作，最终成品才固定版本并独立盲评。当前模型服务连接为阿里云百炼，尚无独立DeepSeek适配，不能把DeepSeek Key填进百炼连接框。

发布排程和复盘

先完成一个账号的闭环

  1. 确认品牌知识、授权素材和预算，完成当前计划版本的一次成品及盲评试运行；检查每个账号子任务的成品。
  2. 在内容工作室选择固定成品版本，处理内容检查提示并完成独立盲评，再点击安排发布，选择明确账号和时间。
  3. 在独立联调环境，由部署人员开启应用与发布节点的真实发布开关，负责人授权机构发布。确认该次操作将向外部账号提交后，再执行首次真实作品。
  4. 到官方后台核对发布结果，保存作品ID和链接。当前账号对应发布能力通过真实回执确认；指标能力通过实际作品回收确认。
  5. 负责人在当前计划版本试运行通过、身份及发布能力均核实后，启用计划。正常逐条审核模式仍需审核后排期。

日历和运行记录

  • 发布日历的计划时段是预排，不保证在该分钟已经公开可见。当前到时才创建运行，素材生成、审核和上传都会影响实际发布时间。
  • 调度处理15分钟内到期的时段，更早错过的时段不会集中补发。保持Worker和调度服务运行；不需要持续打开浏览器或ChatGPT。
  • 任务与复盘显示步骤、成品版本、费用、错误和账号子任务。部分成功时只处理失败账号，已成功作品不重新发布。

异常和数据回收

结果未知时先查询并在官方后台核对，不再次点击发布。暂停会阻止后续新调用和未提交发布；已经提交的付费任务继续查询、保存和结算。明确失败与未知结果采用不同恢复方式。

默认T+3天回收作品指标，缺失不按零计算，可手工补录。不同平台分别查看口径；通过专属预约链接进入的招生可追踪归因，未带来源不推测。

成品修改会形成新版本，原预测保留，新版本需重新盲评和排期。品牌、计划、知识或账号身份变化时，旧任务执行前会重新校验。

部署人员接入说明

本页供部署人员操作。负责人页面不能直接填写任意MCP服务地址；后端只调用平台维护的发布网关。小红书MCP、抖音和视频号浏览器能力均在网关后运行。

配置项用途和要求
OPS_PUBLISHER_URL应用和Worker可访问的受控网关地址；本机开发通常为 http://127.0.0.1:8900。
OPS_PUBLISHER_TOKEN应用侧网关认证主密钥，至少32位；不填入品牌资料或前端。
PUB_MASTER_KEY生产网关侧使用与应用一致的主密钥，并派生机构级凭证。
OPS_ALLOW_LIVE_PUBLISH 和 PUB_ALLOW_LIVE应用和执行节点两侧真实发布开关；初始均关闭，真实发布联调时按授权启用。
OPS_ALLOW_LIVE_REPLIES 和 PUB_ALLOW_REPLIES回复的两侧开关；当前产品互动暂停，打开开关不能替代功能适配和权限验证。
OPS_MATRIX_SOURCE_HOSTSRSS/Atom HTTPS域名白名单；空值禁用外部Feed。
OPS_MATRIX_MAX_RUNNING每机构运行推进并发，默认2；还受宿主和浏览器资源限制。

Windows开发执行节点默认读取 .local/xiaohongshu-mcp.exe，可通过 scripts/build-mcp.ps1 构建。仅下载MCP源码不会自动接入网页；执行节点还需Chromium和依赖。生产镜像中包含固定版本的MCP执行程序。

真实账号使用独立环境

  1. 使用独立端口，例如8192，另建数据库、数据目录、应用主密钥和发布节点状态；OPS_DEMO_MODE=false。不得指向8188及现有外网演示的数据库或状态卷。
  2. 先部署固定版本的发布网关、Chromium和小红书MCP。Windows开发节点与生产rootless Docker节点是两种部署路径。
  3. 在独立测试机构创建负责人、品牌和账号，先保持真实发送关闭，检查网关健康、扫码、可靠身份和只读能力。
  4. 配置模型、单价、额度和预算后，进行有成本的成品试运行；再分别联调真实发布、作品回读和T+3指标。
现有 scripts/dev.ps1 -Publisher 使用常规开发配置，不会自动建立独立真实账号环境。请先显式配置独立数据库等资源，避免覆盖已有工作区。不要把此脚本当作独立联调环境的一键创建工具。

生产发布镜像和网关当前使用0.4.0 rc1，版本以publisher/compose.yaml及镜像锁为准。浏览器节点与客户财务数据库隔离，不公开裸网关端口；跨主机采用受限私网TLS接入。

故障排查和交接核对

现象处理方式
演示环境拦截扫码登录目前在企业演示。保留演示，切换到独立账号联调环境。
发布执行节点尚未连接运维核对网关地址、认证密钥、节点健康、网络可达性和浏览器安装。
没有二维码或二维码过期检查节点是否运行及账号上下文；重新获取登录图，使用对应平台应用逐个扫码。
已连接但身份待核验核对连接器是否回读真实账号ID。抖音待真实页面验证，视频号稳定ID尚待适配。
核验能力后仍不能自动发布检查真实发布回执、当前版本试运行、账号和机构预算、负责人授权及两端发送开关。
额度或预算不足检查平台额度或所选自带Key、机构月、账号月、计划日与单次预算及预占。
已改计划但旧任务停止使用新版本重新试运行和授权，不能让旧任务静默改投新账号。
发布超时或结果未知先查官方作品和任务回执，保留待核实，不盲目重新提交。
评论 私信或微信客服不可用当前功能暂停；按能力状态到官方后台人工处理，不能只打开环境开关。

首次真实接入的交接清单

  • 机构、账号实际身份、品牌和分组对应正确；凭证互不覆盖，同平台重复绑定得到拦截。
  • 记录应用版本、计划版本、知识版本、预算、发送授权人和测试时间。
  • 保留真实作品编号、链接和官方核对记录；模拟测试、协议测试与真实账号测试分开。
  • 验证重登、账号暂停、权限撤销、服务重启及未知结果处理；停止旧的重复发送调度后再切换。
