知营 ai-ops-saas：给接手的 GPT / Codex 的项目上下文
整理日期：2026-10-25
源码基线：0.4.0-rc2；数据库 head：0006_deepseek

一、用户要做什么

这是面向教育培训机构创业者的 AI 辅助经营工作台。“一人公司”指一个人可以兼任多个职位，也支持多人协作。
负责人通过“成员与授权”管理成员的一项或多项职能。核心业务为招生录入/扫描、跟进试听、报名收款、班级与学员档案、排课签到、教师课返完成 KPI、经营周报月报、异常提醒、财务票据与图表、自媒体矩阵。
各机构独立；教师默认看任教范围，招生默认看本人负责记录，营收查看权限不能扩大财务/学员权限。

二、已确认边界

- 新报名直接填写项目、金额、优惠和购买课时，不依赖课程包；历史课程包保留。
- 课返只记录是否按期完成，不提供课返内容编辑、AI生成或家长自动发送。
- 网页/微信 AI 客服和社媒评论、私信自动回复保持暂停。
- 数字人直播供应商未接通，主菜单当前隐藏；不是已经能真实开播的功能。
- 金额为整数分，收退款、课时和分润由后端规则计算；AI不能绕过财务审批或业务校验。
- 周报月报采用固定指标口径，保留历史快照。AI解读是负责人按需创建的独立任务，只使用汇总数字。

三、DeepSeek 接入

已增加官方 API 文字适配、负责人配置、显式费用来源、预占/结算、供应商和计价快照、输入/缓存/输出 Token 记录、连接测试。
Key 按机构加密，服务端调用；没有将真实 Key 写入仓库。
文字生成、选题、分镜规划、复盘、OCR 后结构化整理和报表解读可选择 DeepSeek。
图片、视频、配音、向量检索、视觉盲评及独立复核继续走百炼独立模型。
矩阵计划明确选择自己的费用来源，不自动切换平台 Key 与机构 Key。
已排队任务保留模型/计价快照，Key撤销或岗位失效时仍重新检查；不明确的付费调用不会盲目重发。
入口：机构负责人 → 机构与连接 → 服务连接 / AI模型配置。

四、自媒体矩阵

多品牌、多分组、同平台多账号；员工按岗位访问本机构账号。负责人管理凭证、预算、账号绑定及自动发布策略。
固定步骤：采集 → 选题 → 分账号文案/分镜 → 媒体生成/合成 → 成品版本 → 独立盲评 → 审核或发布 → T+3数据回收 → 复盘。
每次运行固定明确账号列表，账号分别隔离登录态和任务锁。成功作品必须有可核实编号和链接；结果未知先核实。
原个人自媒体工程不作为运行依赖，不导入个人历史内容、Cookie、私信或模型凭证。

七、运行与继续开发

使用依赖锁文件；按 README 安装虚拟环境与前端依赖，先用 scripts/configure.py 生成本机独立 .env，不要把示例空配置直接覆盖生产配置。
GitHub 不包含运行时依赖、业务数据库、上传目录、浏览器登录状态或 Key。GitHub上传也不会部署一个可访问的网站。
不要访问或推测原开发机器的 E: 盘路径；克隆后用仓库相对路径与当前机器配置。
先读文件、确认接口和验收状态，再提出或实现新需求。测试用隔离数据，演示成品与模拟回执不能冒充真实平台发布。
