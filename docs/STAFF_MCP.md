### 启动

仅预览业务功能：

    .\scripts\dev.ps1

准备本地 MCP（首次）：

    .\scripts\build-mcp.ps1 -InstallTools
    .\.venv\Scripts\python.exe -m pip install -r publisher/requirements.lock
    $env:PLAYWRIGHT_BROWSERS_PATH = "$PWD\.local\browsers"
    .\.venv\Scripts\python.exe -m playwright install chromium

随后启动网站与本地发布网关：

    .\scripts\dev.ps1 -Publisher

该命令在本机后台启动仅监听 127.0.0.1 的开发网关，保留真实发布和回复开关的既有配置。开发网关禁止在 production 环境运行；生产环境必须采用独立 Linux 主机与 rootless Docker 网关。

本地构建使用固定 Go 1.27.3 工具链，下载归档 SHA-256 会校验；不会安装到全局。浏览器使用 Python Playwright 对应版本的标准 Chromium。模型调用仍需要有效凭证和额度。

## 岗位与数据边界

- 负责人管理本机构业务、成员、岗位、业务分配和自动化授权；平台管理员没有隐含的机构业务访问权。
- 招生只看本人负责的线索、订单及其关联资料、会话，不能登记收退款。
- 教师通过任课班级和报名关系读取本班资料，能签到和填写反馈草稿，不能排课、调整课时或修改财务。
- 教务管理全机构教务，订单只展示必要付款状态；财务查看账务与必要学员基础资料，不获得课堂记录或私信权限。
- 内容运营管理机构内容与自媒体互动，不获得招生台账、财务或教学资料权限。
- 兼任按每个操作和数据字段分别授权。教师兼财务可以看账务，但不会因此看到其他老师的课堂记录。
- 相同规则用于搜索、计数、详情、附件、导出和后台任务。角色/归属改变后，任务执行前重新检查；浏览器每15秒及重新聚焦时刷新权限。
- 关联线索的会话跟随线索负责人，旧会话负责人字段不会继续授予权限。未分配线索只对负责人开放。

在“机构与连接 → 团队与岗位”邀请员工、选择兼任岗位或停用成员。邀请24小时有效、绑定邮箱、只能接受一次；已有账号填写当前密码，新账号填写姓名和新密码。接受邀请不创建额外机构。系统保留至少一名有效负责人。

## 三平台能力

| 平台 | 已实现的连接器 | 尚待真实账号验证 / 人工方式 |
|---|---|---|
| 小红书 | 固定源码的独立 MCP 进程；扫码、图文/视频发布、本人作品核实、评论读取与回复适配 | 真实扫码、发布、评论及指标需要联调；当前上游没有私信工具，保留人工入口 |
| 抖音 | 现有发布执行器通过统一 MCP 提供图文/视频发布；官方评论接口凭证管理和适配 | 官方权限、账号关联、真实发布和评论需联调；私信回调有验签/去重存证，消息体与收发接口尚待账号专项验证，当前走人工 |
| 微信视频号 | 现有视频发布执行器通过统一 MCP 接入 | 不支持图文；评论和私信保持未接通，使用官方后台人工处理 |

在“发布与复盘 → 平台能力与自动回复”逐账号查看能力、原因、授权和默认招生负责人；负责人在“机构与连接”添加账号并扫码。抖音官方凭证按账号加密保存，页面只允许替换，不回显。

“可用”只由成功的连接/读取或真实回执产生，不通过填写配置直接宣称已验证。暂时未验证的回复可由负责人在真实发送已启用的联调环境使用自有测试账号核实；其他员工使用已验证能力。

真实发布需要应用 `OPS_ALLOW_LIVE_PUBLISH=true`、节点 `PUB_ALLOW_LIVE=true` 和机构发布授权；真实回复需要 `OPS_ALLOW_LIVE_REPLIES=true`、节点 `PUB_ALLOW_REPLIES=true`、负责人策略及对应能力验证。本地预览默认不发送外部消息。

### 发布与回复核实

小红书上游只返回“发布完成”，本产品会比较发布前后本人作品，取得唯一新作品编号和链接后才判定成功。没有明确结果时停在待核实，不自动重复提交。评论回复同样需要外部回执或本人回复核实；结果不明确时转人工。

MCP 网关仅开放受控工具，拒绝浏览器 Origin 和越权租户请求。每机构隔离环境，每账号独立进程、强制绝对 Cookie 路径及随机服务令牌；登录状态加密保存，明文只用于临时目录。生产临时目录为 tmpfs，浏览器和凭证不与业务数据库共处执行环境。

## 自动回复与人工处理

- 仅处理用户发起的互动，按机构、平台账号和事件编号去重，忽略本人消息。
- 自动回复依据当前已审核的资料生成，并检查来源版本、价格冲突和宣传规则。
- 资料不足、退款争议、人工要求、费用/权限不足或平台限制转人工，保留回复草稿和原因。
- 人工接管取消待发任务；发送前再次检查状态与权限。发送结果未知不自动重试。
- 未接通渠道可人工录入实际收到的评论或私信、生成草稿、打开官方后台处理，并直接登记外部处理结果。外部登记不会冒充系统发送成功。
- 自媒体咨询可转为线索，按账号配置分配到有效招生人员；没有配置则由负责人分配。
- 自动轮询间隔60秒，错误时退避，连续失败暂停并要求重新检查登录和权限。

## 数据升级与运行

生产先备份数据库、对象存储、主密钥和发布节点状态，再运行 Alembic 升至 `0002_staff_social`。SQL 审查文件 `migration-upgrade-0002.sql` 包含从空库初始化到新版本的完整语句，不要直接对现有库重复执行。

升级将旧 operator 岗位转换为招生、内容运营、教务三个岗位，原 role 字段保留兼容；已有 owner/teacher/finance 保持原义。不能确定归属的旧数据仍由负责人处理。新表执行强制机构 RLS；旧审计、收退款和课时历史不重写。

本地 SQLite 初始化执行同义的追加升级，并在本次开发前保存了 `.local/backups/before-staff-mcp.db`。生产恢复和回滚需在 Linux、原生 PostgreSQL、真实对象存储上另行验收，不能用 WASM 检查代替。
